# Planning / discovery pack

- Inspect existing README, build manifests, entry points, tests and exact request before choosing the stack.
- For a fresh project, write concise acceptance criteria (features, nonfunctional requirements, locale, persistence, deployment target), milestones and a decision log.
- Favor existing working technologies unless there is a measurable reason to switch.
- Ask for confirmation only on material ambiguity, irreversible operations, real spending or sensitive permission changes.
- Maintain a small task checklist or checkpoint file when work spans sessions; do not reload massive histories.
- External inspirations: `github/spec-kit`, `obra/superpowers`, `addyosmani/agent-skills`. They are references, not imported dependencies.
