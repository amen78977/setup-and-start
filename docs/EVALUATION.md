# Evidence required for a high-confidence evaluation

Ratings are judgments, not executable guarantees. A passing regression suite does
not establish maximum model intelligence, professional visual quality on every
project, lower billing or universally independent review.

Current local evidence:

- 111 tests completed: 109 passed, two Windows-specific checks skipped on Linux.
- Real Chromium capture passed for an Arabic RTL page at mobile/desktop sizes.
- The 19 offline routing fixtures passed; these measure selection, not coding quality.
- Regression coverage includes tracked source in cache-named directories, skipped
  suites behind alternative launchers, auth assertions, incomplete source evidence,
  source/screenshot identity, failure diagnosis and resume discovery deduplication.

Remaining evidence required before claiming top performance in every category:

| Category | Required evidence |
| --- | --- |
| Professional outcomes | Independent acceptance checks on representative backend, frontend, security and multi-component projects, including unsuccessful trials. |
| UI/UX quality | Actual screenshot and journey inspection by a trusted independent inspector; artifact hashes alone do not prove inspection. |
| Cost and tokens | Complete provider counters or actual billed costs for paired native-agent/skill trials; unknown usage stays unknown. |
| Independence | Actual provider/model identity and reviewer permissions, beyond distinct CLI labels or user assertions. |
| Autonomy | Recorded intervention counts and successful bounded delegation/integration in supported host runtimes. |
| Portability | Completed Windows and Linux CI jobs, plus real CLI adapter checks against supported authenticated versions. |

Use the protocol in MEASUREMENT.md and `benchmarks/compare_runs.py` for matched
observations. Keep acceptance conditions and environments equal, repeat trials
and assess quality alongside cost. No paid-provider A/B trial or new remote CI
execution has been performed by the local tests documented here.
